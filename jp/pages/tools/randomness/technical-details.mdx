製品概要については [Solana VRF](/jp/pages/verifiable-randomness-functions-vrfs/introduction/solana-vrf) を参照してください。

ランタイムの概要については [Ephemeral Rollup ドキュメント](/jp/pages/get-started/introduction/ephemeral-rollup) を参照してください。

MagicBlock は `ephemeral_vrf_sdk` を通じて、ランダムネスを第一級のプリミティブとして提供します。Rollup プログラムは `caller_seed` と `consume_randomness` のようなコールバックを使って `create_request_randomness_ix`（`RequestRandomness` 命令）を呼び出します。その後、MagicBlock Solana VRF ネットワークのオラクルが `ProvideRandomness` 命令を実行して結果を返します。

乱数は Curve25519 の Ristretto グループ上に構築された VRF によって生成され、RFC&nbsp;9381 に記載された Schnorr 風署名で証明されます。証明と出力は、MagicBlock VRF signer PDA からの署名付きコールバックによって rollup に返されます。プログラムは呼び出し元を検証し、その後ゲームロジックでランダムネスを使用します。

`random_u32`、`random_u8_with_range`、`random_bool` のようなヘルパーユーティリティを使うと、`[u8; 32]` の出力を扱いやすい値に簡単に変換できます。リクエストと消費のステップはどちらも一時的な実行ウィンドウ内で行われるため、ユーザーは外部サーバーに依存することなく、検証可能に公平なリアルタイム結果を得られます。

## フロー

<img class="w-full h-auto max-w-5xl" src="/images/vrf-flow.png" />

フローは「ランダムネスのリクエスト」から始まります。

1. あなたのプログラムは CPI で MagicBlock VRF プログラムを呼び出し、リクエストをキューに追加します。
2. ランダムネスのリクエストがキューに入ると、オラクルがそのリクエストを処理し、ランダムネス計算を行います。
3. 完了すると、結果と証明が MagicBlock VRF プログラムに返されます。
4. 証明が検証された後、VRF プログラムはあらかじめ定義された関数を通じてあなたのプログラムへコールバックし、ランダムネスを「消費」させます。

<Note>
  VRF プログラムには公開済みの監査があります。本番 rollup に統合する前に、レポートを確認し十分にテストしてください。
</Note>

## オラクルキュー

すべてのランダムネスリクエストは、**オラクルキュー（oracle queue）**アカウント（`RequestRandomnessParams` の `oracle_queue` フィールド）を指定します。他のすべての Solana アカウントと同様にこのキューも Solana 上に存在しますが、**委任された（delegated）**キューは ephemeral rollup の内部からのみ直接書き込み可能で、**委任されていない**キューはベースレイヤーで直接書き込み可能です。トランザクションが実行される場所に合ったキューからランダムネスをリクエストしてください——Solana ではベースレイヤーのキューを、ephemeral rollup 内部では委任されたキューを使用します。可能な限りアドレスをハードコードせず、`ephemeral_vrf_sdk::consts` の定数を参照してください。

| ネットワーク | ベースレイヤーキュー                                                        | 委任されたキュー（ephemeral rollup）                                                     |
| ------------ | --------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| Mainnet      | `DEFAULT_QUEUE`<br />`Cuj97ggrhhidhbu39TijNVqE74xvKJ69gDervRUXAxGh`          | `DEFAULT_EPHEMERAL_QUEUE`<br />`5hBR571xnXppuCPveTrctfTU7tJLSN94nq7kv7FRK5Tc`            |
| Devnet       | `DEFAULT_QUEUE`<br />`Cuj97ggrhhidhbu39TijNVqE74xvKJ69gDervRUXAxGh`          | `DEFAULT_EPHEMERAL_QUEUE`<br />`5hBR571xnXppuCPveTrctfTU7tJLSN94nq7kv7FRK5Tc`            |
| Localnet     | `DEFAULT_TEST_QUEUE`<br />`GKE6d7iv8kCBrsxr78W3xVdjGLLLJnxsGiuzrsZCGEvb`     | `DEFAULT_EPHEMERAL_TEST_QUEUE`<br />`Sc9MJUngNbQXSXGP3F67KvKwVnhaYn6kcioxXNVowYT`        |

<Note>
  Mainnet と Devnet は同じデフォルトキューアドレスを使用します——異なるのは接続するクラスターだけです。Localnet は専用の**テストキュー**を使用し、これはローカルバリデーターが Devnet から複製します。`DEFAULT_TEST_QUEUE` / `DEFAULT_EPHEMERAL_TEST_QUEUE` 定数は VRF SDK に同梱されています。
</Note>
